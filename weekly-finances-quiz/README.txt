LIVE CAPTCHA
Cloudflare Turnstile replaces Yandex SmartCaptcha. The widget is managed mode,
English, dark theme, with the quiz_complete action. Worker Siteverify requires
success=true, exact production hostname, and the exact action. Missing keys,
expired or replayed tokens, provider errors and mismatches block completion.
The API accepts a token only. Answers and amounts never leave the tab.
Public settings are in wrangler.jsonc. TURNSTILE_SECRET must be a Worker secret,
never a source file or browser value. Preserve secret bindings during deploys.
Build the site module with npm run build:worker before deploying.
GitHub Pages remains an explicit static preview without live verification.

ANALYTICS
Metrica is enabled by default when a real counter is configured. Explicit opt-out
in Privacy is respected; no consent popup interrupts the quiz.
No Webvisor, clickmap or automatic link tracking. No answer values or amounts
are sent. Campaign params and funnel event names are sent while analytics is on.
No purchase event is generated by the quiz UI. App Store clicks are not purchases.
APP_STORE_CAMPAIGN_URL accepts only HTTPS apps.apple.com links for id6756235224.
Use a real campaign link from App Store Connect, with its provider token.

PRIVACY AND SCOPE
Quiz answers are memory-only and reset on reload. The optional money calculation
is (monthly income - committed spending - planned savings) * 12 / 52.
Negative balances remain a gap; missing figures are not replaced with zero.
No LLM, account, bank connection, email collection, trial or payment checkout.
The personal plan is a rule-based starting routine, not financial advice or
a psychometric score. Answers are not transferred into the app.

APPLE NOTIFICATIONS
Production and sandbox V2 notifications have separate /api/apple/notifications/
endpoints. A D1 ledger retains verified transaction information, without quiz
answers. PAYMENT_ATTRIBUTION_ENABLED=1 issues an appAccountToken after successful
Turnstile verification when analytics permission and a ClientID or yclid are
available. PAYMENT_EXPORT_ENABLED remains 0 pending device/sandbox verification
and Metrica OAuth configuration. See payments/DEVELOPER_HANDOFF.txt.
Run npm run build:deploy before deploying the bundled Worker. Preserve secrets.

APP OPENING AND RETURN AFTER INSTALLATION
The result includes a plain link to
https://financialplan.pistonsky.dev/open?token=<appAccountToken>.
The link host serves the AASA file; the canonical path is /open, without a slash.
Only the server-issued UUID, its expiry and a storage version are persisted under
wf-app-handoff-v1. No quiz answers, financial amounts, ClientID or yclid are saved
in that record. The 21-day expiry matches the server attribution window.
Reloading the quiz restores an app-opening screen with the same UUID and does
not resubmit /api/complete or send another quiz_complete goal. Start a new plan
clears the browser record. Expired/corrupted records are ignored.
After installation, return to the original quiz tab and tap Open Weekly Finances.
The App Store cannot pass this UUID into a fresh install automatically.
If browser storage is unavailable, the link still works in the current page,
but cannot be restored after a reload. Without analytics identifiers the normal
quiz and App Store links work, with no fabricated attribution token.
app_open_click is only an opening intent; it is not an installation or payment.
